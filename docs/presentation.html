Context & Motivation
The Quick-Commerce Problem
⏱️
10-15 Min SLA Pressure

Dark stores operate on razor-thin margins. A single stockout or rider bottleneck triggers severe cascading cancellations and customer defection.

📉
Dashboards Only Show "What"

Power BI and Tableau report that revenue is down 23%, but store managers don't know WHY it happened or WHAT operational action to take next.

🤖
LLM Hallucination Risk

Querying an LLM directly on database questions leads to invented numbers. Enterprise decisions require 100% deterministic mathematical verification.

💡 Our Solution: Decision Intelligence combining Deterministic SQL (Numbers) + Predictive ML (Forecasts) + Generative AI (Reasoning).

🛡️ Anti-Hallucination Design (Core USP)
  • Strict Division of Responsibility: Python/SQL executes all arithmetic; Gemini receives ONLY pre-computed numbers.
  • Zero Direct DB Access for LLM: The model cannot run exploratory queries or invent phantom metrics.
🔄 Proactive vs. Reactive Shift
  • Predictive Triggers: 7-day demand forecasting alerts store managers BEFORE stock runs out.
  • Automated Interventions: Automated apology coupons dispatched to churning accounts.
Layer 1 — Data Foundation
Relational Database & Anomaly Injection
11-Table Schema in 3NF (54,900+ Records)
  • stores (10 records): Dark stores across Delhi, Bengaluru, Gurugram, Noida.
  • products (~200 records): SKU catalog with category, price, shelf-life.
  • orders (3,000+ records) & order_items (~9,000): High-frequency transactions.
  • inventory (54,900 records): 90-day daily closing stock per SKU per store.
  • delivery_logs (2,848 records): Fulfillment latencies & ratings.
  • 3 ML Output Tables: demand_forecasts, churn_scores, delivery_predictions.
Embedded Real-World Anomalies
  • Store 3 (QuickMart Koramangala): Fleet starvation (only 5 riders) + severe stockouts (33.48%) → 30.5 min ETA (100% SLA risk) → -23.57% MoM revenue collapse & 2.15/5 rating.

  • Control Stores (Store 1, 2, 5): Stable operational benchmarks (<14 min ETA, <8% stockout).

Layer 3 — Machine Learning Module 1
SKU-Level 7-Day Demand Forecasting
Time-Series Formulation
  • Architecture: 610 Store-SKU XGBoost Regressor models trained across 54,900 sales records.
  • Feature Engineering: Lags (y_lag_1, y_lag_7, y_lag_14), Rolling Means & Std (7-day), Day of Week.
  • Restock Prediction: Recursive 7-day forward horizon predicting unit demand per SKU.
Automated Restock Alert Logic
  • If Predicted 7-Day Demand > Current Stock: Trigger RESTOCK_ALERT.
  • Execution Results: 577 store-SKU restock alerts triggered automatically.
  • Store 3 Finding: Amul Paneer 200g (Stock: 20, 7-Day Demand: 67) → Stockout in 2.1 days!
  • Auto-populates MySQL demand_forecasts & generates PO notifications.
Layer 3 — Machine Learning Modules 2 & 3
Customer Churn & Dynamic Delivery ETA Engines
Module 2: Customer Churn Classification
  • Model: XGBoost Classifier with 12 behavioral features (days_since_last_order at 45.6% impact, order frequency, spend, ratings).
  • Validation: 94.40% Accuracy, ROC-AUC = 0.8357, 5-Fold CV AUC = 0.8684 ± 0.0600, Precision = 93.33%, Recall = 70.00%.
  • Outcome: Flagged 61 HIGH-risk accounts (>70% churn prob) → ₹100 retention voucher dispatched (~800% ROI).
Module 3: Dynamic Delivery ETA Engine
  • Model: XGBoost Regressor trained on 2,848 delivery fulfillment records.
  • Metrics: MAE = ±2.74 min, RMSE = ±3.22 min, R² = 42.6% (urban stochastic traffic noise).
  • Key Driver: rider_capacity drives 89.0% of delivery latency.
  • Store 3 Insight: Predicts 30.5-min fulfillment time (100% SLA breach risk) directly exposing the 5-rider bottleneck.
